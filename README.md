# SAGE — AI 驱动的 SE 自适应成长引擎

> SE Adaptive Growth Engine · 面向 SE 团队的 AI 能力评估与学习系统

SAGE 将能力评估、知识盲区诊断、个性化学习计划和后测验证串成一个闭环，帮助 SE 用数据了解自己的能力，也帮助管理者了解团队能力分布。

## 当前版本

当前版本已经完成从单一 Big Data 演示到多 Profile、多服务能力评估平台的扩展：

- 支持 Profile 注册、登录和切换，不同 Profile 显示对应的服务范围
- 覆盖 Big Data、Analytics、Database、Deployment、Networking & Security、SCD、Linux、Windows 等方向
- 服务和能力点由当前 taxonomy 配置提供；管理页的 Profile 列表随配置自动更新
- 支持动态出题、智能评分、知识盲区诊断、学习计划生成和后测验证
- 使用自研固定顺序的角色分工工作流完成诊断、规划、反思与有界修订，并展示步骤记录；未依赖 AutoGen/CrewAI
- 出题、评分和后测使用异步任务加轮询，避免长时间 LLM 请求触发 504
- 集成 RAG 检索能力，可从知识库中检索相关学习资料
- 管理员可查看按 Profile 过滤的团队能力看板
- 提供 Chatbot 形态的模拟客户工单实战：自动加载当前 Profile 的全部服务，覆盖 7 类技术支持工单和 8 种客户画像；业务背景、故障场景、证据、标准排查步骤、诊断思路、根因、方案和验证方式经过“生成、独立评审调用、最多一次修订、硬规则校验”后整体冻结，多轮客户会话按状态逐步释放证据；普通沟通、最终总结和带逐字引用的六维 AI 复盘都在同一聊天流中完成
- 学习计划任务可提交完成证据；档案可重开历史测评报告

评分说明：选择题按答案计 0/5 分；开放题按难度使用不同维度，并提高技术准确性的权重。报告展示所有题目的平均分，但 L2/L3 定级还要求相应难度及开放题证据；少量题或高难度覆盖不足时只展示本次成绩，不给可靠能力等级。工单复盘按澄清 15%、证据 20%、技术判断 25%、方案 20%、沟通 10%、验证 10% 计算；确无机会观察的维度不计入分母，关键技术或方案项低分时总分最多 59。两类报告都保留评分版本；旧开放题原分数不追溯改写。评分权重和档位仍需用人工标注样本校准。

以上是本地代码能力，不代表云端部署已同步。预置案例仅作为生成种子，所有新工单都要经过质量门禁并保存来源、评审结果和不可变快照。AWS 参考资料会先验证并优先采用 AWS 中国中文页，其次采用全球站中文页，最后才回退英文页。来源链接与同模型的独立评审调用不等于 AWS 专家认证；界面会区分 `supported`、`needs_review` 和 `unverified`。客户不会因关键词直接泄露全部证据，建议修改也只记录为待验证动作。AI 反馈是教学参考，不是专家人工评分或真实 AWS 环境验证。

## 核心流程

```
选择 Profile / 服务 / 模型 → AI 出题（绑定模型与来源）→ 提交答案并评分
                                                     ↓
能力雷达图 ← 盲区诊断 → 学习计划 → 反思检查 → 必要时最多修订一次
                                                     ↓
                                 学习后后测验证并对比能力变化
```

## 技术栈

| 层 | 选型 |
|---|---|
| 前端 | Next.js 16 + React 19 + TypeScript + Tailwind CSS 4 + ECharts |
| 后端 | Python 3.12 + FastAPI + Pydantic v2 + SQLAlchemy 2 |
| 数据库 | SQLite（开发与演示） |
| LLM | OpenAI 兼容协议，可配置云端或内部部署模型 |
| 检索 | RAG 服务与本地知识库 |

## 快速开始

### 环境准备

- Python 3.12
- Node.js 20+
- 可访问的 OpenAI 兼容 LLM 服务及 API key

### 配置后端

```powershell
Copy-Item backend/.env.example backend/.env
# 编辑 backend/.env，填写 LLM_API_KEY、LLM_BASE_URL 和 LLM_MODEL
```

启动后进入“能力测评”，可在出题前选择模型并刷新模型列表。后端会从 OpenAI 兼容服务的 `/models` 接口发现可用模型；若服务商不支持该接口，则只提供 `LLM_MODEL` 默认模型。本轮出题、评分、诊断和学习计划沿用所选模型；新增模型后重新刷新列表即可选择。

### 启动后端

```powershell
cd backend
pip install -r requirements.txt
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

API 文档：http://localhost:8000/docs

正式部署请先将 `APP_ENV=production`、至少 32 位的随机 `AUTH_SECRET` 和站点的 `CORS_ORIGINS` 写入环境配置，再在 `backend` 目录运行 `python -m app.cli create-admin --username <管理员名>`。普通成员用 `python -m app.cli create-member --username <成员名>` 创建；命令会交互式读取密码，不会使用演示账号。生产环境默认关闭自助注册，只有显式设置 `PUBLIC_REGISTRATION=true` 才开放。升级已有实例前运行 `python -m app.cli backup --output <新备份文件路径>`；命令不会覆盖现有文件。当前自动迁移仅支持加列，失败时会中止启动，尚不能替代正式迁移系统。

所有新安装均不预置账号或密码。首次使用前在 `backend` 目录运行 `python -m app.cli create-admin --username <管理员名>`，按提示设置独立密码；已有本地数据库的账号不会被删除。管理员从登录页的“管理员入口”进入团队看板，在“账号管理”中创建成员或其他管理员并重置密码；管理员权限不能通过公开注册取得。

### 启动前端

```powershell
cd frontend
npm install
npm run dev
```

访问：http://localhost:3000

前端默认通过同源 `/api` 转发到本机后端 8000 端口；前后端分机部署时，在 Next.js 服务端设置 `SAGE_BACKEND_URL`。只有确需浏览器直连后端时才设置 `NEXT_PUBLIC_API_BASE`。同源转发可避免浏览器限制跨本地端口访问导致登录失败。

## 体验流程

1. 注册或登录账号。
2. 选择 Profile、服务和能力点。
3. 生成并完成测评题目。
4. 查看评分、能力雷达图、知识盲区和学习计划。
5. 在“我的档案”查看进行中的学习计划。
6. 为学习任务记录实验/复盘证据，或进入“实战练习”：从当前 Profile 选择服务、工单类别、客户画像和模型，也可设置业务影响、难度和跨服务依赖；创建与报告生成在后台执行，刷新页面可继续轮询；至少两轮后提交结案方案，查看澄清、证据、技术判断、方案、沟通和验证六维报告及其原文依据。
7. 完成学习后进入后测，比较前后能力变化；档案中的历史报告可再次打开。
8. 管理员进入团队看板，查看团队能力分布和培训建议；可向当前 Profile 培训名单布置同服务、固定题量/难度的任务，复核用户纠错与学习证据，并查看知识覆盖、后台任务耗时/失败率。

报告可直达同服务再测；仅当存在样本足够且低分的能力点时才预选专项再测，也可进入同服务工单创建页。历史页支持服务、状态和关键词筛选；档案显示管理员任务和纠错复核状态。用户提交学习证据只进入“待验收”，管理员核对后才标为“已验收”。

知识库仅检索已审核发布的案例/官方正文；同一服务的重复资料会被阻止发布。新增或更新资料只重嵌发生变化的片段，管理员仍可显式全量重建。更新已发布资料时使用“创建新版本”：新版本发布时旧版原子下架，原记录保留供审计。

## 本地验收

```powershell
cd backend
python -m unittest discover -s tests -t . -v
python -m app.scripts.benchmark_rag
cd ../frontend
npm run lint
npm run build
```

当前验收覆盖认证与用户隔离、题目答案隐藏、异步任务结果恢复、工单质量硬门禁、客户状态与证据释放边界、报告逐字引用、学习证据等。自动化测试不能代替 AWS 专家抽样评审。
此前本机已从 DeepSeek 兼容接口发现 2 个模型，两个模型均完成真实 9 题出题；默认模型还完成一次前测、评分、诊断、学习计划、后测和历史报告复开。新工单已完成一次真实模型的“生成 + 评审 + 硬规则”创建验收及新手画像的分步证据请求；专业准确性与评分一致性仍需更大样本和人工评审。无模型时可体验旧版固定练习。
仓库已提供 GitHub Actions 检查配置（后端隔离测试、前端 lint/构建）；只有推送并查看 Actions 结果后才能宣称远端 CI 通过。
检索基准使用 5 条固定案例查询，报告 `hit@5` 和本机延迟；样本量很小，不能等同于线上召回率或全链路性能。

## 安全提示

- `backend/.env`、数据库、日志和模型密钥不应提交到 Git。
- 请使用 `backend/.env.example` 创建本地配置，并通过环境变量管理密钥。
- 不内置演示账号密码；本地试用账号也须自行初始化，勿复用真实环境密码。
- 生产环境必须设置至少 32 字符的 `AUTH_SECRET` 和正确的 `CORS_ORIGINS`；不会自动创建演示账号。
- `LLM_DEBUG` 默认关闭，避免原始 Prompt 和作答写入日志。后台任务负载会持久化，单进程重启后可重放；这不是多实例分布式队列。
- 运行面板只从本次更新之后采集后台任务的模型 token 和执行耗时；同步客户对话、历史任务不包含完整用量。只有明确配置 `SAGE_LLM_PRICES_JSON` 且用量齐全才显示费用估算；不要把“未知”当零成本。
