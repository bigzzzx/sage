# 远端 Embedding / Rerank 召回对照（2026-09-30）

本次在本地 SAGE 知识库上，经临时 localhost-only SSH 隧道调用用户指定的 Ubuntu 服务器已有 `/embed` 和 `/rerank` 服务。远端只执行推理；不创建远端文件，不修改模型服务或 SAGE 线上检索配置。全量组传输了内部案例内容，已获用户明确授权。

## 方法

- 对同一批服务过滤后的候选，比较：现有 BM25 + 中英别名扩展 + RRF、远端向量、两者 RRF 融合、融合后远端重排；最后均按根文档去重，只保留 Top-5。
- Embedding 为 512 维，语料仅在客户端进程内嵌入一次。重排服务内存限制较紧，测试按每批 2 段请求评分。
- 公开组：13 个 AWS Glue 公开事实问题、164 个官方正文/事实片段。全量组：15 个固定案例问题、232 个知识片段（官方资料、内部案例、学习路径）。
- 指标中的 Hit@K 是预标注目标文档进入前 K 名的比例；MRR@5 是目标文档的倒数排名均值。延迟是查询侧均值，不含语料首次 Embedding；网络/隧道延迟已计入远端方案。

| 数据集 | 方案 | Hit@1 | Hit@5 | MRR@5 | 平均查询耗时 |
| --- | --- | ---: | ---: | ---: | ---: |
| 公开 Glue | BM25 | 9/13 | 13/13 | 0.846 | 3.8 ms |
| 公开 Glue | 远端向量 | 8/13 | 12/13 | 0.718 | 72.1 ms |
| 公开 Glue | 混合 RRF | 11/13 | 12/13 | 0.885 | 76.0 ms |
| 公开 Glue | 混合 + 重排 | 9/13 | 13/13 | 0.846 | 4465.4 ms |
| 全量案例 | BM25 | 14/15 | 15/15 | 0.967 | 4.2 ms |
| 全量案例 | 远端向量 | 14/15 | 15/15 | 0.967 | 70.5 ms |
| 全量案例 | 混合 RRF | 14/15 | 15/15 | 0.967 | 74.7 ms |
| 全量案例 | 混合 + 重排 | 13/15 | 15/15 | 0.933 | 1906.1 ms |

公开组语料首次 Embedding 约 18.1 秒，全量组约 24.3 秒；这不是单次查询耗时。首次尝试一次重排 16 段时，远端服务断开并重启；改为每批 2 段后完成测试。该服务容器本身已有较高历史重启次数，不能把这一次现象解释成模型质量问题，但接入前必须验证并发与容量。

## 判断与限制

这批数据上，远端向量没有提高 Top-5 召回；重排在全量组的 Top-1 还下降一题，延迟增加约 1.9 秒。暂不建议切换线上默认检索，先保留 BM25 方案。

这些问题由现有知识库编写，数量少且跨服务被过滤后部分服务候选极少；这不是独立、盲测的真实用户流量，也不能证明语义召回在未来复杂问法中无效。Glue 安全组问题存在两份高度相似案例，预标注仅指向其中一份，因此 Top-1 的 14/15 也受到标注口径影响。下轮应补充真实匿名问法、无答案/多相关文档问题和按服务分层的人工标注，再决定是否引入模型。

复现脚本：`python -m app.scripts.benchmark_public_remote_rag`（只发送公开资料），以及经数据所有者授权后运行 `python -m app.scripts.benchmark_remote_rag`（发送全量语料）。两个脚本只接受本机回环地址的模型 API；调用前需自行建立通往获授权服务器的临时 SSH 隧道。
