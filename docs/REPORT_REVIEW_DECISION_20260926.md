# 学习报告评审编排：当前工程结论（2026-09-26）

## 结论

**保留现有的“生成 → 一次独立评审 → 至多一次修订 → 硬规则复核/待人工确认”路径；暂不增加第二评审 Agent，也不引入多轮讨论或 DeepAgents。** 这是一项保守的工程选择，不是“单评审在统计上最优”的证明。评审机制未能稳定修正事实和教学任务问题，增加轮次的收益不够抵消时延/费用；更应优先完善证据约束、评审误报过滤、任务前置条件和真实样本验收。已有 LangGraph 图只承载明确状态和有界回路，不需要增加讨论节点。

## 关键质量观察

- NAT 样本五组共享的诊断已对齐题干；单评审修订补上了规则组延期的同一公网目标前后验证，但其任务仍假设预置 Glue/VPC 环境，45 分钟内实施 NAT 变更和回滚不可凭文本证实。
- 双评审版把 **S3 VPC Endpoint** 与 NAT 并列为修复“公网 API 不通”的可选方案；[AWS S3 Endpoint 文档](https://docs.aws.amazon.com/glue/latest/dg/vpc-endpoints-s3.html)只证明 S3 私网访问，不能支持任意公网 API。这是本轮唯一明确计数的事实错误。
- 审稿人有误报：输入 fixture 明确给出 L1/L2 等级，却批评等级无依据；[AWS 中国区网络文档](https://docs.amazonaws.cn/en_us/glue/latest/dg/start-connecting.html)和[故障排查文档](https://docs.amazonaws.cn/en_us/glue/latest/dg/troubleshooting-connection.html)是真实官方文档，不能仅因与全球区 URL 不同就判无效。Crawler 讨论组还删除了“Data Catalog 是集中元数据目录”，尽管 [AWS Catalog 文档](https://docs.aws.amazon.com/glue/latest/dg/catalog-and-crawler.html)正是这样定义的。
- 所有组都缺少已经执行过的 AWS 实操证据，故任务可执行性均未给 2 分。题目要求的前后对照不能用桌面推演、不同执行环境的 EC2 测试或假设可用的示例 URL 冒充。引用评分为 1 并不表示官方材料本身错误，而是报告的部分相邻断言缺精确出处或有空 URL。

## 适用边界与下一步验收

两个合成样本、一个模型、一个种子不足以证明任何策略优越；共享诊断也意味着本实验**无法测出评审能否改善诊断**。用户授权 Codex 做来源核查，但 AI 的一次核查不能冒充两名 AWS Glue 专家独立标注。因而当前可以做“暂不升级多 Agent 编排”的产品决策，不能宣称完成统计/专家认证。

上线扩展编排的门槛：先补充脱敏真实案例，预先固定最小有意义改善幅度；由两名不同的懂 Glue 的人员独立盲评事实、诊断、引用、任务可执行性并仲裁分歧；在相近 Token 预算、多个种子和模型下复跑；将 AWS 实操任务在隔离、预置环境里计时执行，记录成功率、资源费用与清理/回滚。若不能达到门槛，继续单评审加确定性约束，并让证据不足的计划标为 `needs_review`。

## 结论后的定向改造

按上述结论，已在现有单评审流程中传入测评等级，明确全球区/中国区官方来源不能仅凭域名差异判错；计划生成与评审都区分任意公网 API 的 NAT 出口和仅用于 S3 的 Endpoint。学习任务新增 `preconditions`、`verification_steps`、`risk_and_cleanup`，前端可直接展示；涉及资源变更但缺少这些信息、或把 S3 Endpoint 当作公网 API 出口的计划会触发确定性问题，不能直接标成通过。对“不要创建/修改”等否定句作了防误报处理。历史运行数据与上面的对照表**未重算**，不能将新逻辑的效果回填为旧实验结果。

本地回归为 46 项后端测试通过，前端 lint/build 通过。`deepseek-v4-pro` 的一份合成两日 Glue 计划实际生成了全部新增字段、两项任务均为 45 分钟，硬规则通过；模型评审仍给出 4 项待处理问题，故这是**执行链路 smoke**，不是内容质量通过或 AWS 实操验收。
