# 评分质量验证（2026-09-28）

## 范围与方法

使用项目当前生产评分函数、已配置的 `deepseek-flash` 模型，对 10 份 AWS Glue 测评答案和 4 段模拟工单会话进行一次实测。样本由评测者预先编写，覆盖正确、部分正确、冗长但错误、以及另一种正确表达；评测者随后逐项核对分数、理由、证据引用和是否误称“已执行/已验证”。这是小规模定性校准，不是独立专家盲评，也不能证明跨服务、跨模型的评分可靠性。

可复现脚本：`backend/app/scripts/evaluate_scoring_quality.py`。原始结果：`data/evals/scoring_quality_flash_20260928.json`。脚本直接调用生产评分函数，不修改业务数据库。

人工事实核对依据：[AWS Glue Data Catalog 与 Crawler](https://docs.amazonaws.cn/glue/latest/dg/catalog-and-crawler.html)、[Job Bookmark](https://docs.amazonaws.cn/glue/latest/dg/monitor-continuations.html)、[Glue VPC 连接](https://docs.amazonaws.cn/glue/latest/dg/connection-JDBC-VPC.html)。

## 观察结果

| 场景 | 正确 | 部分正确 | 明显错误 |
| --- | ---: | ---: | ---: |
| Crawler 测评（5 分制） | 5.0；另一种正确表述 5.0 | 1.8 | 1.4 |
| Bookmark 测评（5 分制） | 4.8 | 2.0 | 1.0 |
| VPC/NAT 测评（5 分制） | 4.5 | 1.9 | 1.0 |
| VPC/NAT 工单（100 分制） | 78 | 49 | 2 |
| Crawler 功能咨询工单（100 分制） | 85 | — | — |

正误分差明显，冗长错误答案未得到高分；工单评语引用的会话证据可在原文中找到，未发现把“建议执行”当成“已经验证”的误判。但下面的偏差需要修正，不能因为总体排序正确就忽略。

1. 简短但技术上正确的 Crawler 答案被给了 `事实准确性 2/5`。遗漏关键点应主要扣完整性，不应当成错误事实。Bookmark 的部分答案也出现类似混淆。
2. VPC/NAT 正确答案的评语因没有显式附 AWS 文档而扣分，但题干没有要求引用文档。这是评分规则超出题目要求。
3. 模拟工单的强答案在“验证与收尾”只得 `3/5`，理由包含没有真实执行结果。当前训练环境没有提供实际执行通道；可执行的验证计划应该和执行结果分别评价，不能仅因未执行扣计划质量分。
4. 错误工单的评分曾因模型输出结构不合格重试一次。14 个案例总计 15 次模型调用，提示词 17,132 token、输出 44,557 token、累计等待约 207 秒；工单评分单次约 30–40 秒，成本和延迟值得继续优化。

## 修订与定向复测

修订后，评分提示明确区分事实准确性与遗漏内容；未被题目要求的官方文档引用不再是扣分项。模拟工单的“验证”维度评价计划质量，不因训练环境没有执行入口而单独扣分。针对“只说了一句正确事实，却没有回答核心问题”的情况，准确性仍独立保留，但完整性 ≤2 时总分封顶 3.0（完整性 ≤1 时封顶 2.5）。新测评记录标记 `assessment_v3`，新工单评分标记 `ticket_v3`；历史分数不追溯改写。

同样使用 `deepseek-flash`，重新跑了四个受影响案例，结果保存在 `data/evals/scoring_quality_flash_20260928_retest.json`：

| 样本 | 原分 | 修订后 | 复核 |
| --- | ---: | ---: | --- |
| Crawler 部分回答 | 1.8 | 首次 3.8；加完整性封顶后再测 3.0 | 准确性保持 5/5，完整性 2/5；不再把遗漏当事实错误，也不让片面回答得到高总分 |
| Bookmark 模糊回答 | 2.0 | 1.8 | 只说“可能跟脚本有关”，没有可核验的技术判断，准确性 3/5 可接受；其余维度低分 |
| NAT 正确回答 | 4.5 | 4.5 | 反馈不再以“未附官方文档”为由扣分；仍指出实施与前后因果解释不够具体 |
| NAT 强工单 | 78 | 78 | 验证维度由 3/5 升至 4/5；剩余缺口是回滚触发条件、验证证据留存和交接责任人，不是“未执行” |

完整性封顶后的 Crawler 再测原始记录：`data/evals/scoring_quality_flash_20260928_final_check.json`。本轮 85 个后端回归测试通过；截图中 `docs.amazonaws.cn/en_us/glue/latest/dg/start-connecting.html` 经真实 HTTP 获取与历史计划展示逻辑解析，均转到中文的 `https://docs.amazonaws.cn/glue/latest/dg/start-connecting.html`。

## 结论与边界

本轮发现的三项可复现偏差已修正，并用受影响样本做了定向实测。评分可以继续用作训练反馈；但 14 个首轮样本与 4 个复测样本不足以证明跨服务、跨客户画像或多次运行的一致性。尤其模型评分本身仍有随机波动，不能宣称达到 AWS 专家评审、正式绩效考核或认证水平。下一步应扩充到 profile 中每个服务与等级，包含边界答案、多次重复运行和人工盲审；工单评分的约 30–40 秒延迟也仍需优化。
