## 当前实现

前测评分仍由 `services/assessment.py` 完成。之后的 `diagnose → planning → review → 可选 revise → finish` 使用 LangGraph 编排，节点复用现有业务函数。每个测评会话使用稳定的 `assessment:{user_id}:{session_id}` 检查点 ID；SQLite 检查点默认保存在 `backend/sage-workflow-checkpoints.sqlite`，可用 `SAGE_WORKFLOW_CHECKPOINT_PATH` 覆盖。该文件包含用户答题和评分内容，必须与业务数据库一样保护和备份。

图内完成的节点可在相同检查点上恢复。提交请求的具名负载在 `background_tasks` 表中先保存再执行，进程启动时重排未完成任务。提交任务按用户和会话去重。执行并发上限为 2。失败的学习流程保留评分，用户可以从报告页继续生成计划。

当没有可靠知识缺口时，图不生成补弱计划；存在低分或诊断失败时标记 `needs_review`，不会把“未识别缺口”写成“能力已掌握”。

用户可在出题前设置 1–7 个学习日和每天 30–180 分钟；预算保存在题目会话，计划的任务数和单日时长按此校验。时间不够时，major 缺口可以在计划中明确延期，critical 缺口仍要求覆盖。默认 5 天/90 分钟沿用五天模板，并补充时间上限；非默认预算使用弹性模板。模型评审现收到实操、故障练习、时长及诊断证据，空或结构不完整的评审输出不再视为通过。

## 可靠性边界

- 当前后台执行器只面向单进程部署。多实例需要外部任务队列、租约/心跳和数据库迁移；启动重排不能代替分布式协调。
- 检查点按节点持久化。服务若在开放题评分尚未进入图之前退出，该题评分可能重新调用模型；在图节点内已发出但未完成检查点的模型请求，也可能重试并再次计费。
- 出题作业在模型调用前预分配会话 ID。会话已保存但任务尚未完成时，重放复用原试卷；模型调用已发出但会话尚未保存时仍可能重复计费。
- SQLite 自动迁移仅支持加列。正式多实例部署需要 PostgreSQL 和版本化迁移。
- 自动审查通过仅表示流程与规则检查通过，不代表 AWS 技术事实或诊断语义获得专家认证。

## 后续质量评估

已新增离线对照协议与执行器，详见 [报告策略对照](REPORT_COMPARISON.md)：固定初稿比较规则、单审查、独立证据/教学双审查、限定轮次讨论，以及同为四次审查调用但不交换意见的预算基线。记录 API 尝试、Token、延迟与可选费用；支持双人盲评事实错误、错误诊断、引用支持、学习任务可执行性。运行指标不代替人工质量标签。

目前只有两份合成 Glue 样本；尚缺领域专家对报告逐项双人标注、分歧仲裁，以及更大规模脱敏真实样本。共享诊断在五组相同，故该实验不能衡量不同审查策略改善诊断本身的能力。只有人审质量收益稳定且成本合理时才考虑增加线上 Agent；出题语义审核仍需单独验收。
